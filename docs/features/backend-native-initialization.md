# 설치본의 수치 라이브러리 초기화

Windows 설치본은 NumPy의 네이티브 DLL을 백엔드 메인 스레드에서 먼저 초기화한다. API 요청 스레드와 백그라운드 작업은 그 뒤에 시작한다. 문서 검색을 처음 요청한 스레드에서 DLL을 처음 불러오면 Windows 로더 잠금과 새 요청 스레드의 시작 대기가 겹쳐, 챗봇뿐 아니라 문서 읽기·상태 확인 요청도 응답하지 못할 수 있다.

이 단계는 NumPy 초기화만 담당한다. 임베딩·재순위화·OCR 모델은 기존 기능별 런타임이 필요한 시점에 로드한다. 개발용 Python 실행에는 설치본용 선행 초기화를 적용하지 않는다.

챗봇의 문서 검색과 선택 영역 근거 읽기는 Electron이 기록한 외부 파일별 허용 정보를 사용한다. 저장 폴더 밖의 파일도 사용자가 직접 열어 허용 목록에 등록했다면 읽을 수 있다. 등록하지 않은 다른 파일이나 상위 폴더 전체의 접근 권한은 부여하지 않는다. 파일 변경 작업의 기본 경로 제한은 유지한다.

검증에서는 NumPy 초기화가 API 조립과 스레드 생성보다 먼저 메인 스레드에서 실행되는지 확인한다. 설치본 검증은 기본 상태 확인에 더해 첫 문서 검색과 그 직후의 문서 읽기·상태 확인을 실행해야 한다. 계정 연결 상태와 실제 AI 답변 성공은 별도로 구분하며, 일반 회귀 검사에서 유료 모델을 호출하지 않는다.
