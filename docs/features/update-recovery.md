# 업데이트 검증과 실패 복구

설치 파일은 실행 중인 앱 옆의 별도 폴더에 압축을 푼다. 모든 파일의 크기와 SHA-256, 경로 탈출·중복·연결 폴더 여부를 확인한 뒤에만 앱 종료를 요청한다. 파일과 상위 경로 검사는 .NET 파일 API를 사용하며 검증 중에도 취소 요청을 확인한다. 상태 파일에는 검증한 파일 수와 전체 파일 수를 기록한다.

진행 상태는 완성한 임시 JSON 파일을 Windows 원자적 이름 변경으로 교체한다. 대상 파일을 잠그는 `File.Replace`를 사용하지 않아 구버전 앱의 동시 읽기와 충돌하지 않는다. 파일 검사 프로그램 등으로 이름 변경이 잠기면 이전 상태 파일을 유지하면서 최대 5초 재시도한다. 앱도 상태 파일의 일시적인 `EBUSY`·`EPERM`·`EACCES` 읽기 오류를 최대 10초 재시도하며, 잘못된 JSON이나 세션 불일치는 즉시 실패로 처리한다.

앱 종료 후 이전 설치 안의 사용자 설정과 데이터를 백업·복원하고 디렉터리를 교체한다. 사용자 자료에 포함된 연결 폴더와 백업 대상 경로의 연결은 거부한다. 다만 이전 백업들의 내용이나 이관하지 않는 번들 런타임을 새 백업의 검사 대상으로 삼지 않는다. 백업 실패의 세부 오류는 해당 업데이트 세션에 보존한다.

교체 실패 시 기존 설치를 다시 실행한다. 이후 같은 버전의 자동 설치는 중단하고 실패 이유를 안내한다. 새 버전은 정상적으로 설치할 수 있고, 사용자가 설정에서 업데이트 확인을 직접 실행하면 같은 버전을 명시적으로 재시도할 수 있다.

FFmpeg와 FFprobe가 모두 있으면 다시 다운로드하지 않는다. 새 설치에 포함된 두 파일, 기존 설치에서 보존한 두 파일, `%LOCALAPPDATA%\AILS\tools\ffmpeg`의 캐시 순서로 사용한다. 기존 파일을 복사할 때는 크기와 SHA-256을 검증하며, 새 설치에 하나만 있는 경우에도 기존의 완전한 쌍을 재사용한다. 체크섬을 검증한 다운로드는 이 캐시에도 남겨 업데이트가 취소되거나 실패해도 다음 설치에서 재사용한다. 캐시 저장이 불가능하면 이미 검증한 설치는 유지하고 설치 로그에 그 사실을 남긴다.

준비 완료 후 취소하는 검사만으로 실제 업데이트 성공을 판단하지 않는다. 관련 회귀 검증은 실제 `Finish` 단계에서 앱 종료, 사용자 자료 백업·복원, 디렉터리 교체까지 진행하며 기존 백업의 연결 폴더와 사용자 자료의 연결 폴더를 각각 확인한다.

일반 설치와 삭제도 설치 경로 안의 실행 프로세스와 그 하위 프로세스를 확인한다. 부모 앱이 이미 종료된 백엔드도 종료하며, 다른 설치 경로의 같은 이름 프로세스와 삭제기 자신의 실행 체인은 건드리지 않는다. 프로세스 종료에 실패하면 파일 교체·삭제를 시작하지 않는다.

실제 삭제에서는 설치 폴더의 개인 설정·작업 초안·재개 자료를 외부 백업에 보존하고 FFmpeg 쌍을 재설치용 캐시에 남긴다. 설치 폴더의 연결 파일·폴더는 연결 자체만 제거하며 대상 경로는 탐색하지 않는다. 읽기 전용 파일과 일시적인 잠금은 처리·재시도하되, 폴더가 남으면 실패를 알리고 삭제 완료로 처리하지 않는다. 이 경우 앱의 등록 정보도 유지해 다시 삭제할 수 있다.
